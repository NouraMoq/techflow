# صانع المحتوى | Content Maker — Production build (Next.js)

تطبيق **Next.js 14 (App Router) + TypeScript** حقيقي وقابل للتشغيل لمنصة «صانع المحتوى» من
نوفاميتريكس، مع **Prisma + قاعدة بيانات**، **مصادقة آمنة**، **RBAC**، و**تعدد عملاء (Multi‑Tenancy)**
بعزل صارم. الواجهة عربية RTL وتعيد استخدام نظام تصميم النموذج.

> **قاعدة البيانات:** للتطوير المحلي هنا تُستخدم **SQLite** (لعدم توفّر PostgreSQL/Docker في البيئة).
> المخطط مكتوب بطريقة **محمولة** (بدون enums/arrays خاصة بـ Postgres — الحقول enum كنصوص، وقوائم
> JSON كنصوص). **التحويل إلى PostgreSQL في الإنتاج** = تغيير `provider` في `prisma/schema.prisma`
> إلى `postgresql` و`DATABASE_URL`. راجع `../docs/database-design.md`.

## التشغيل

```bash
cd content-maker
npm install --legacy-peer-deps      # (البيئة تحتاج legacy-peer-deps)
npm run prisma:generate             # توليد Prisma Client
npm run prisma:push                 # إنشاء مخطط قاعدة البيانات
npm run seed                        # بيانات عربية تجريبية
npm run dev                         # http://localhost:3000
```

أمر واحد لإعادة ضبط القاعدة وإعادة البذر: `npm run db:reset`.

## ما الذي يعمل فعليًا (تم التحقق منه في المتصفح)
- **مصادقة**: كلمات مرور مُجزّأة بـ bcrypt، جلسة موقّعة (JWT/HS256 عبر `jose`) في كوكي httpOnly، تسجيل دخول/خروج.
- **Multi‑Tenancy**: كل استعلام محصور بـ `tenantId` من الجلسة — عميل لا يرى بيانات عميل آخر (مثبت ببذر حسابين).
- **RBAC**: `can(role, permission)` يحكم الأزرار والإجراءات (كاتب لا يستطيع الاعتماد، عارض للقراءة فقط، إلخ) — مع اختبارات Vitest.
- **إجراءات خادم (Server Actions)** مع تحقق **Zod**: إنشاء فكرة، نقل فكرة، قرار موافقة، إنشاء علامة/فرصة، تقديم الفرصة في المسار — كلها تكتب للقاعدة وتُسجّل في **Audit Log**.
- **صفحات مبنية على البيانات**: الرئيسية، الاستراتيجية، الأعمدة، بنك الأفكار (Kanban)، الإنتاج، المهام، الموافقات، مكتبة الملفات، **الحملات والإعلانات (CRM)**، **العقود والفواتير**، التحليلات (تجريبية موسومة)، الفريق (مصفوفة RBAC)، ولوحة نوفاميتريكس (العملاء + الباقات + سجل التدقيق).

### الوحدات التجارية والأصول
- **الحملات والإعلانات** (`/campaigns`): CRM مصغّر — لوحة فرص (Opportunities) قابلة للتقديم بين المراحل، جدول العلامات التجارية وجهات الاتصال، والحملات مع التسليمات (Deliverables) ونسبة الإنجاز.
- **العقود والفواتير** (`/contracts`): سجل العقود (قيمة/مدة/حصرية/حقوق استخدام/حالة دفع)، **تنبيهات الالتزامات التي قد تُنسى** (انتهاء الحصرية/الحقوق، بقاء المنشور، التسليم، الدفعات — مع تمييز المتأخر)، وجدول الفواتير والمستحقات + سجل المدفوعات.
- **مكتبة الملفات** (`/assets`): مكتبة أصول رقمية — مجلدات، أنواع، إصدارات، وسوم، و**تنبيه انتهاء حقوق الترخيص**. تُخزَّن `storageKey` (مفتاح S3) لا روابط عامة/أسرار.

### التقارير القابلة للتصدير (مضافة)
- **التقارير** (`/reports` + `/reports/[type]`): ٧ تقارير (تنفيذي، المحتوى، الأعمدة، الفريق والإنتاجية، العقود والالتزامات، الإيرادات والمدفوعات، الامتثال) بعرض **جاهز للطباعة** (زر «طباعة / حفظ PDF» عبر `window.print()` مع CSS طباعة يخفي شريط النظام) و**تصدير CSV** فعلي.
- طبقة بيانات واحدة (`src/lib/reports.ts` → `getReport`) تُستخدم من **عرض HTML و CSV معًا** (DRY)، وكلها **بيانات فعلية معزولة حسب الحساب**.
- تصدير CSV عبر **Route Handler** (`/api/reports/[type]`) يقرأ الجلسة، يتحقق من صلاحية `report.export`، ويعيد `text/csv` مع `Content-Disposition: attachment` و**BOM** لعرض العربية في Excel.

### بوابة العميل المبسّطة للمشهور
- **بوابة المشهور** (`/portal`): تجربة **مبسّطة مركّزة مناسبة للجوال** بتخطيط مستقل **بلا شريط جانبي** (لا تعقيد لوحة الوكالة). تجمّع ما يهمّ المشهور: **ما يحتاج موافقته** (أزرار اعتماد/طلب تعديل كبيرة)، تصوير قادم، خطة الأسبوع، المحتوى القادم، مؤشرات، عقد/فرصة مهم، تنبيهات، و**تسجيل فكرة سريعة** تدخل بنك الأفكار مباشرة. يعيد استخدام إجراء الموافقات، مع تكامل بين الوحدات (فكرة سريعة → بنك الأفكار). رابط ذهاب/عودة بين البوابة واللوحة الكاملة.

### الجمهور والأسئلة + التوصيات الذكية
- **الجمهور والأسئلة** (`/audience`): جدول الأسئلة (تكرار/تصنيف: سؤال متكرر/فرصة محتوى/إعلان محتمل/تصعيد/حالة)، قوائم **الردود المعتمدة** و**الكلمات الحساسة**، و**«حوّل لفكرة»** ينشئ فكرة في بنك الأفكار (تكامل بين الوحدات). إدخال يدوي فقط — لا Scraping ولا جمع غير مصرّح.
- **التوصيات الذكية** (`/recommendations`): محرّك قواعد يولّد التوصيات **من بيانات الحساب الفعلية** (`src/lib/recommendations-engine.ts`) — توازن الأعمدة، ترند يوشك الانتهاء، فاتورة متأخرة، التزام قريب، فكرة معتمدة بلا سيناريو، فكرة عالية الملاءمة، وتيرة نشر منخفضة — وكل توصية تسجّل **الأساس** الذي اشتُقّت منه ومستوى الثقة والمسؤول. **لا اختلاق أرقام**؛ «تطبيق» يحوّل التوصية إلى **مهمة** (تكامل بين الوحدات).

### محرر السيناريو والتقويم التحريري
- **السيناريوهات** (`/scripts` + `/scripts/[id]`): محرر احترافي بكل حقول السيناريو (Hook/مقدمة/جسم/CTA/نص على الشاشة/وصف/هاشتاقات/موسيقى/ملابس/موقع/مدة/إفصاح إعلاني)، **سجل إصدارات**، سير مراجعة (مسودة→مراجعة→معتمد/طلب تعديل)، و**وضع Teleprompter** (`/scripts/[id]/teleprompter`) بنص كبير وتحكم في السرعة والحجم — مناسب للجوال. التحرير يتطلب `script.write`؛ الاعتماد يتطلب `content.approve` (المحرر للقراءة فقط لمن لا يملك صلاحية الكتابة).
- **التقويم التحريري** (`/calendar`): عرض شهري يجمع الأحداث من **٥ مصادر** (عناصر يدوية + جلسات التصوير + تسليمات الحملات + نهايات العقود + استحقاق الفواتير)، مرمّز بالألوان مع مفتاح، تنقّل بين الأشهر، تمييز اليوم، وتنبيه توازن (لا نشر مخطّط / أيام عدم نشر). إضافة عنصر أو يوم عدم نشر تتطلب `content.schedule`.

### جلسات التصوير ورادار الترندات
- **جلسات التصوير** (`/shoots`): بطاقات أيام التصوير (تاريخ/موقع/فريق/تكلفة/حالة) مع آلة حالة (مسودة→مخطّطة→مؤكّدة→جارية→منتهية)، و**قائمة لقطات (Call Sheet)** لكل جلسة — كل لقطة (سيناريو/ملابس/حالة) قابلة للتحديث (بانتظار→تم التصوير→معتمد) مع عدّاد إنجاز.
- **رادار الترندات** (`/trends`): بطاقات ترندات (نوع/صوت/هاشتاق/درجة نمو/عمر متوقع/ملاءمة/مخاطر/زاوية مقترحة) مع قرار (قيد الدراسة/استخدام/تجاهل/مُستخدَم) وإضافة يدوية. **إدخال يدوي وبيانات تجريبية فقط — لا Web Scraping ولا جمع غير مصرّح** (المصادر الرسمية عبر طبقة التكامل لاحقًا).

### تخزين الأصول — S3 حقيقي + مزوّد محلي (Adapter)
- **مكتبة الملفات** (`/assets`): **رفع فعلي** للملفات عبر مزوّد تخزين مجرّد (`src/lib/storage/`): `S3StorageAdapter` (AWS SDK v3 — `PutObject` + **Presigned GET** للتحميل) يعمل عند وجود مفاتيح `S3_*`، وإلا `LocalStorageAdapter` (قرص محلي `.storage/` + روابط موقّعة مؤقتة بنفس عقد S3).
- **أمان**: تحقّق من النوع/الحجم (٥٠MB، أنواع مسموحة) قبل التخزين؛ الرفع **من الخادم** (المفاتيح لا تصل الواجهة)؛ التحميل عبر نقطة `/api/storage/asset/[id]` (مصادقة + عزل بالحساب) تُعيد التوجيه إلى **رابط موقّع مؤقت** (Presigned/محلي) — لا كشف لمفاتيح أو روابط دائمة.
- **مُتحقَّق منه E2E**: رفع ملف فعلي ثم تنزيله واسترجاع نفس البايتات عبر الرابط الموقّع.

### طبقة تكامل TikTok — Adapter Pattern + Mock Provider
- **البنية** (`src/lib/integrations/`): واجهة `PublishAdapter` موحّدة (`connect`/`refresh`/`publish`/`getAuthUrl`)، `MockTikTokAdapter` (محاكاة كاملة دون شبكة/حساب حقيقي)، `TikTokAdapter` (هيكل حقيقي **يرمي `IntegrationNotConfiguredError` حتى تتوفر بيانات الاعتماد** — لا ادّعاء تكامل)، و`registry` يختار المزوّد المباشر عند وجود المفاتيح وإلا التجريبي. إضافة منصة جديدة = تسجيلها في الـ registry فقط.
- **التكاملات** (`/integrations`): Integration Hub بآلة حالة (غير متصل/متصل/يحتاج إعادة تصريح/انتهت الصلاحية/مشكلة/متوقف)، ربط/فصل/إيقاف عبر المحوّل، وبانر «الوضع التجريبي (Mock)» عند غياب بيانات الاعتماد.
- **النشر على TikTok** (`/publishing`): تجهيز مهمة نشر (يتطلب اتصالًا)، ثم النشر عبر المحوّل — **لا تُعلَّم «منشور» إلا إذا أعاد المحوّل نجاحًا مؤكَّدًا بمعرّف**؛ غير ذلك «فشل». يدعم أيضًا **تسجيل رابط منشور يدويًا** (المرحلة الأولى). كل مهمة تحمل وسم الوضع (تجريبي/مباشر).
- **الأمان**: `OAuthConnection.tokenRef` يخزّن **مرجعًا لمخزن الأسرار** (`secret://…`) لا الرمز الخام أبدًا؛ لا نشر آلي غير رسمي؛ لا طلب كلمات مرور حسابات TikTok.

### الامتثال والسمعة والأزمات
- **الامتثال** (`/compliance`): تشغيل مراجعة امتثال على المحتوى التجاري عبر قائمة تحقق (نعم/لا/لا ينطبق) تحسب الحالة تلقائيًا (مطابق/يحتاج معالجة) وتحفظها؛ سجل المراجعات؛ وبنود القائمة الفعّالة. تنبيه بأن المراجعة النظامية النهائية تحتاج مختصًا مرخّصًا.
- **السمعة والأزمات** (`/crisis`): تسجيل المواقف بدرجة خطورة/مصدر/رد مقترح/ردود ممنوعة/حالة اعتماد، ربطها بأدلة استجابة (Playbooks)، وتحديث حالة الأزمة عبر مراحلها، مع شبكة أدلة الاستجابة الجاهزة.
- **إعدادات الامتثال (إدارة)** (`/admin/compliance`): **قائمة التحقق قابلة للتفعيل/التعطيل من لوحة نوفاميتريكس** (لأن الأنظمة تتغير) — البنود المعطّلة لا تظهر في المراجعات الجديدة.

## الاختبارات والمراجعة
- **وحدة (Vitest) — ٢١ اختبارًا**: صلاحيات RBAC، محوّلات التكامل، وحوارس رفع الملفات (النوع/الحجم/التعقيم).
- **E2E (Playwright) — ١٧ اختبارًا**: تقود **Google Chrome النظامي** (`channel: "chrome"` بلا تنزيل متصفح)، وتُعيد بذر القاعدة قبل التشغيل لحالة معلومة، وتغطّي:
  - **المصادقة**: إعادة التوجيه للدخول، دخول العميل، دخول الإدارة، رفض كلمة مرور خاطئة.
  - **RBAC والعزل**: منع العميل من لوحة الإدارة، **عزل بيانات العميل** (لا تسرّب فكرة حساب آخر)، وصول الإدارة عبر الحسابات، تصدير CSV يتطلب مصادقة (401).
  - **التدفّقات**: إنشاء فكرة، اعتماد، بوابة المشهور، تصدير CSV مُصادق، بانر الوضع التجريبي، تقرير مطبوعي، **رفع ملف وتنزيله عبر رابط موقّع**.
- **مراجعة أمنية (اجتيزت)**: كل ٢٥+ عملية كتابة محصورة بـ `tenantId`؛ كل إجراء خادم و Route Handler محميّ بـ `requireSession/requireAdmin` + `assertCan`؛ لا أسرار في المصدر؛ الجلسة كوكي httpOnly موقّع؛ لا Tokens خام في القاعدة (مراجع `secret://` فقط).

## الأمان
- لا أسرار في الكود؛ `.env` و`*.db` في `.gitignore`. كلمات المرور مُجزّأة. لا Tokens في السجلات.
- المخطط يحمل `createdBy/updatedBy/timestamps/deletedAt` (حذف ناعم) على الكيانات الحساسة + `AuditLog`.

## النشر (Docker + PostgreSQL + CI)
انظر **[DEPLOYMENT.md](DEPLOYMENT.md)**. باختصار: `docker compose up --build` يشغّل PostgreSQL + التطبيق
بتكافؤ dev/prod. المزوّد يُبدَّل إلى PostgreSQL عند البناء (`scripts/use-postgres.sh`) دون المساس
بتطوير SQLite المحلي. الـ CI (`.github/workflows/content-maker-ci.yml`) يشغّل الوحدة + البناء، ثم E2E
على PostgreSQL حقيقية.

## الخطوة التالية (لم تُنفّذ بعد)
تفعيل التكامل المباشر مع TikTok (تسجيل التطبيق + OAuth + Scopes + بيانات اعتماد حقيقية — البنية جاهزة عبر Adapter)،
رفع/تخزين S3 فعلي + Signed URLs، ترقية المصادقة إلى Auth.js، PostgreSQL في الإنتاج، وطبقة الفوترة الفعلية
(مزوّد دفع سعودي). كلها موثّقة في `../docs/`.
